# Черновик фрагмента 01 по одной расшифровке

Собран из `03-chunks/01_00-02-43_00-04-59.txt` без сверки со слайдами и глоссарием, так, как его выдаёт первый проход модели или торопливого редактора. Ошибки оставлены специально: их находят проверки из `01-checks.md`.

Этот кадр слышат все машины подсети. Машины с другими адресами молчат, а машина с адресом 100.188.1.2 отвечает спросившему обычным кадром. Машина с адресом 100.188.1.2 отвечает спросившему обычным кадром.

Ответ ядро записывает в IP-кэш, то есть в таблицу соответствия IP-адресов и MAC-адресов, которую показывает команда `ip nay`; раньше для этого служила команда `apn`. Пока запись свежая, спрашивать заново не нужно, и следующие пакеты уходят сразу. Запись хранится, пока ею пользуются, а без трафика устаревает, получает пометку «в тейл» и при следующем пакете проверяется заново.

Если никто не ответил, ядро повторяет вопрос ещё два раза и прекращает попытки. Тогда ping пишет `from 192.168.1.10 ICMP host unreachable`. Это наш собственный адрес: ошибку сообщает наше ядро. Такой симптом означает, что соседа с этим адресом в сети нет: он выключен, подключён не тем кабелем или в адресе опечатка.

ARP работает только внутри подсети, потому что широковещательный кадр за её пределы не уходит. Что, если получатель находится в другой подсети?
