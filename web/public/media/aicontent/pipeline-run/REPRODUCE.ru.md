# Как повторить прогон

Эта инструкция повторяет расшифровку и проверки на готовом докладе `talk.mp4`. Пересобирать сам доклад не нужно: он уже есть в комплекте, а команды его сборки записаны в `RUN.md`. Всё ниже выполняется на macOS или Linux в каталоге, где распакован архив `pipeline-run-kit.zip`, и рядом с ним лежит `talk.mp4`.

## 1. Что поставить

- Python 3.10 или новее и ffmpeg.
- whisper.cpp: на macOS `brew install whisper-cpp`, на Linux — сборка по инструкции проекта; программа называется `whisper-cli`.
- Модель `ggml-large-v3-turbo.bin` из репозитория whisper.cpp на Hugging Face (около 1,6 ГБ). На слабом компьютере подойдёт `ggml-small.bin`: она быстрее, но ошибок будет больше, и с нашей таблицей расхождений ваш результат совпадёт хуже.
- Плагин video-to-article: `git clone https://github.com/tym83/video-to-article`. Мы запускали его на коммите `469f2c7`.

## 2. Звук для распознавания

```bash
mkdir -p 01-source
ffmpeg -i talk.mp4 -ar 16000 -ac 1 01-source/audio.wav
```

Файл получится около 40 МБ, поэтому в архив мы его не положили.

## 3. Расшифровка

```bash
whisper-cli -m ggml-large-v3-turbo.bin -f 01-source/audio.wav -l ru -osrt -otxt -of my-transcript
```

На MacBook Air M4 с моделью large-v3-turbo это заняло около трёх минут. Сравните `my-transcript.txt` с нашей расшифровкой `02-transcript/transcript.txt`: на другой модели или версии whisper.cpp слова будут немного отличаться, а галлюцинация на 2:51–3:08 может повториться на том же месте или появиться в другом: такие повторы модель пишет непредсказуемо, и поэтому их ищут в каждой новой расшифровке заново.

## 4. Фрагменты и проверки плагина

Скрипты плагина работают с каталогом прогона. Чтобы не затереть наши файлы, скопируйте комплект в отдельный каталог и запускайте в нём:

```bash
P=путь/к/video-to-article/skills/video-to-article/scripts
python3 $P/chunk.py .
python3 $P/coverage.py . --mode clean
python3 $P/proofcheck.py 04-text/01.md --lang ru
```

`chunk.py` разбивает расшифровку на фрагменты в `03-chunks/`. `coverage.py` сравнивает длину каждого фрагмента с текстом в `04-text/`: принятый раздел `01.md` проходит, остальные семь помечены как отсутствующие, потому что их ещё никто не отредактировал. `proofcheck.py` ищет повторы, опечатки и типографские ошибки в принятом разделе. Файл `proofcheck.md` в корне комплекта — запись более ранней проверки сырой расшифровки `02-transcript/transcript.txt`, а не принятого раздела: в нём одно замечание, повтор «что что».

## 5. Своя редактура

Возьмите любой фрагмент, кроме `03-chunks/01_00-02-43_00-04-59.txt`, который мы уже довели до раздела `04-text/01.md`, например `03-chunks/02_00-05-00_00-08-00.txt`. Файлы пронумерованы с нуля, поэтому номер в имени на единицу меньше порядкового. Пройдите с выбранным фрагментом тот же путь, что и мы:

1. Дополните глоссарий `05-review/glossary.md` терминами своего фрагмента.
2. Напишите черновик по одной расшифровке.
3. Сверьте его с текстом докладчика `talk-source.txt` и запишите каждое расхождение в таблицу, как в `05-review/01-checks.md`.
4. Положите принятый текст в `04-text/NN.md` и снова запустите `coverage.py` и `proofcheck.py`.

Если в вашей таблице меньше пяти строк, перечитайте фрагмент ещё раз рядом с записью: на этом докладе почти в каждом фрагменте есть искажённые команды и числа.
