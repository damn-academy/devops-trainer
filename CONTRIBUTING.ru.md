# Как поучаствовать в DevOps Trainer

[English](CONTRIBUTING.md) · Русский

Курс открыт, и его можно улучшать: исправлять ошибки и неточности, переписывать непонятные места, добавлять задания, схемы и уроки, чинить симуляторы. Этот файл рассказывает, как устроен репозиторий и как оформить изменение, чтобы его можно было быстро принять. Тот же текст есть в самом курсе, на странице «Справка о курсе → Как поучаствовать» (`#/about/contribute`).

## Как устроен репозиторий

Весь курс лежит в одном репозитории [damn-academy/devops-trainer](https://github.com/damn-academy/devops-trainer).

- `web/` содержит само приложение на TypeScript и Vite без UI-фреймворка. В `web/src/core` лежат типы, реестр, маршрутизатор, хранилище и линтер, в `web/src/app` страницы, в `web/src/engine` движки (терминал, схемы, вопросы, документация, симуляторы, v86, нейросеть, офлайн), в `web/src/blocks` содержание блоков, по каталогу на блок, а в `web/tests` и `web/e2e` тесты.
- `design/` содержит проектную документацию, главный документ в ней [`design/00-DESIGN.ru.md`](design/00-DESIGN.ru.md).
- `lab/` содержит лабораторию dtlab на Go ([`lab/README.ru.md`](lab/README.ru.md)).
- `service/feedback/` содержит сервис обратной связи на Go ([`service/feedback/README.ru.md`](service/feedback/README.ru.md)).
- `tools/terraform-provider-lab/` содержит провайдер Terraform для облака во вкладке.
- `deploy/` содержит конфигурацию nginx, манифесты Kubernetes и скрипты выкладки ([`deploy/README.ru.md`](deploy/README.ru.md)).

Блоки и движки подключаются сами: реестр находит их через `import.meta.glob`, поэтому общий список, который нужно править при добавлении блока, отсутствует.

## Как запустить курс и тесты

Для работы над курсом нужны Node.js и npm, а для лаборатории, сервиса и провайдера ещё Go.

```bash
cd web
npm ci
npm run dev                       # http://localhost:5173 с заголовками изоляции
npm run typecheck                 # проверка типов TypeScript
npm test                          # модульные тесты и линтер порядка понятий
npm run lint:explainers           # проверка текстов схем
npx playwright install chromium   # один раз перед первым запуском e2e
npm run test:e2e                  # сквозные тесты в браузере
```

Тесты на настоящем v86 по умолчанию пропускаются и включаются переменными, например `V86_LAB=1 npx vitest run tests/v86-lab-integration.test.ts`; для них сначала нужно собрать образ командой `npm run build:lab-image`. Программы на Go проверяются командой `go test ./...` в каталогах `lab`, `service/feedback` и `tools/terraform-provider-lab`. Перед отправкой изменения проверка типов, `npm test` и линтеры должны проходить без ошибок.

## Как устроены урок, схема и лаборатория

Все формы данных описаны в `web/src/core/types.ts`, а правила подключения собраны в [`web/CONTRACTS.ru.md`](web/CONTRACTS.ru.md). Блок экспортирует модуль через `defineModule` из файла `web/src/blocks/<каталог>/index.ts`: блоки, уроки, понятия, вопросы, схемы, команды, страницы документации и экзамены.

- **Урок** имеет идентификатор вида `<блок>.<название>` и состоит из разделов: `text`, `explainer`, `terminal`, `quiz`, `docs`, `callout` и `widget`. Каждый раздел может быть виден только на некоторых уровнях. Урок перечисляет понятия, которые он вводит (`introduces`) и на которые опирается (`uses`), и каждая строка для ученика задаётся на двух языках через `bi(ru, en)`. Команды, вывод терминала и страницы `man` остаются английскими.
- **Схема** — это модель процесса, которую создают через `defineModel` и подключают через `fromModel`. У модели не больше двенадцати узлов, у каждой линии есть подпись и карточка, у каждого узла есть карточка, а функция `run` по параметрам возвращает шаги процесса. Рабочий пример лежит в `web/src/blocks/demo/pipe.ts`.
- **Лаборатория** — это раздел `terminal` с начальным состоянием машины (`setup`) и заданиями. Цель задания записывается как условие над фактами `dt.facts/v1`, например `files['/srv/index.html'].mode=0644`, а поле `fail` даёт объяснения для типичных ошибок. Линтер не пропускает цель, которая читает набранный текст. Задания на настоящем Linux подключаются виджетом `v86.linux` с тем же форматом целей.

К каждому заданию пишется эталонное решение, а тесты прогоняют его на симуляторе и доказывают, что задание решаемо. У каждого урока есть источники на английском и русском языке с настоящими ссылками.

## Как писать текст

Русский текст курса подчиняется руководству [`web/STYLE-RU.md`](web/STYLE-RU.md), и его правила служат условиями приёмки. Мы пишем полными связными предложениями, без рубленых фраз, без пустых слов-усилителей, без калек с английского и без канцелярита, а примеры всех запретов собраны в самом руководстве. Каждый термин вводится до того, как им пользуются, и называется одинаково в тексте, на схеме и в вопросах. Пример в уроке может опираться только на то, что ученик уже прошёл на маршруте.

Три линтера помогают держать эти правила:

- линтер порядка понятий запускается вместе с `npm test` и не пропускает термин, который встретился раньше вводящего его урока;
- команда `npm run lint:explainers` проверяет все тексты, которые может показать схема;
- скрипт `node scripts/lint-ru-style.mjs <блок>` ищет в русских строках обрывки, предложения на двоеточии вместо глагола и кальки.

Последние два линтера эвристические, поэтому каждую находку стоит прочитать глазами, а перед сдачей страницу нужно открыть в браузере и просмотреть.

## Как сообщить об ошибке

Ошибку в тексте, схеме или задании удобнее всего отправить из самого курса кнопкой «Сообщить о проблеме» или выделив текст и нажав «Комментировать»: сообщение само укажет место в курсе и приложит вывод терминала. Ответ появится на странице «Мои сообщения». Ошибки в коде, предложения по устройству курса и всё, что касается лаборатории dtlab и сервиса обратной связи, лучше описать в [задаче на GitHub](https://github.com/damn-academy/devops-trainer/issues): что вы делали, что ожидали увидеть и что увидели на самом деле, а также браузер и систему.

## Как оформить изменение

Изменение присылают запросом на слияние (pull request) из отдельной ветки, а не в `main`. Сообщение коммита пишется по-английски в формате semantic commits, `type(scope): описание`, где тип — один из `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`, `ci`, `perf` и `build`:

```text
fix(linux): explain why chmod needs the x bit on directories
```

Каждый коммит подписывается командой `git commit --signoff`, которая добавляет строку `Signed-off-by` и подтверждает, что вы вправе передать этот код под лицензией проекта ([Developer Certificate of Origin](https://developercertificate.org/)).

В описании запроса на слияние расскажите, что изменилось и зачем, а для изменений в интерфейсе или в схемах приложите снимки экрана на ширине 1440 и 390 пикселей. Одно изменение должно решать одну задачу: исправление опечатки и новый урок лучше прислать отдельно. Весь публичный текст в репозитории, то есть код, комментарии, коммиты и описания запросов, пишется по-английски, а русский остаётся в текстах курса и в файлах с окончанием `.ru.md`.

## Лицензия

Курс распространяется по лицензии [Apache-2.0](LICENSE), и всё, что вы присылаете, принимается под той же лицензией. Сторонние компоненты сохраняют свои лицензии: эмулятор v86 распространяется по лицензии BSD-2-Clause, пакеты Alpine и ядро Linux по своим лицензиям, которые скрипт сборки образа записывает в манифест рядом с каждым скачанным файлом.
